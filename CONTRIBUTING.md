# Contributing Guidelines

Thank you for your interest in RES.

2026.09 is the final release of Research and Engineering Studio. AWS support for it ends on 2027-09-30.
[`SUPPORT.md`](./SUPPORT.md) has the dates, and [`MAINTAINERS.md`](./MAINTAINERS.md) covers what that
means for stewardship.


## Making changes to RES

Fork the repository and make your changes there. The Apache 2.0 license permits it, and
[`FORKS.md`](./FORKS.md) explains how forks relate to this repository.

Pull requests opened here are not merged.

If you want to keep a fork consistent with how the codebase was built,
[`docs/develop/code-conventions.md`](./docs/develop/code-conventions.md) records the conventions the RES
team applied. They are documented rather than enforced by tooling, so a fork should expect to apply them
by review.


## Reporting bugs and feature requests

You are welcome to use the [GitHub issue tracker](https://github.com/aws/res/issues) while this repository
is open. Please check [existing open](https://github.com/aws/res/issues) and
[recently closed](https://github.com/aws/res/issues?q=is%3Aissue+is%3Aclosed) issues first.

Another user may recognize the symptom. For anything you need an answer or a commitment on, use AWS
Support while RES is supported; [`SUPPORT.md`](./SUPPORT.md) has the dates and the route.

2026.09 is the final release, so no further features are planned.

The details that help most:

* A reproducible test case or series of steps
* The RES version, from `RES_VERSION.txt`
* Any modifications you have made that are relevant
* Anything unusual about your environment or deployment


## Security issue notifications

Please do not create a public GitHub issue for a security report. Follow
[`SECURITY.md`](./SECURITY.md), which gives the reporting route and explains how it changes after
support ends.
